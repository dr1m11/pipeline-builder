# Design tokens

Components never use raw colours. They use Tailwind utilities generated from CSS variables in
`src/app/styles/tokens.css`, so both themes come from one place. Switch the theme in the toolbar to
compare.

## Port types

Each port type has a colour for its connection dot. Colour is never the only cue: ports also show
their type as text, and `any` is drawn as a ring. Each colour keeps at least 3:1 contrast against
`surface` and `surface-muted` in both themes. An edge takes the colour of the port it leaves: the
canvas gives it an `edge-<type>` class, which `tokens.css` maps to React Flow's edge stroke.

## Usage

| Token     | Utilities                                              |
| --------- | ------------------------------------------------------ |
| `canvas`  | `bg-canvas`                                            |
| `surface` | `bg-surface`, `bg-surface-muted`                       |
| `fg`      | `text-fg`, `text-fg-muted`                             |
| `border`  | `border-border`                                        |
| `accent`  | `bg-accent`, `hover:bg-accent-hover`, `text-accent-fg` |
| `danger`  | `bg-danger`, `text-danger-fg`                          |
| `warning` | `bg-warning`, `text-warning-fg`                        |
| `focus`   | `outline-focus`, `ring-focus`                          |
| `overlay` | `bg-overlay`                                           |
| `port-*`  | `bg-port-text`, `border-port-json`, …                  |

Adding a colour means adding a variable for both themes in `tokens.css` and mapping it in the
`@theme inline` block of `index.css`.

## Motion

Dialogs, menus and toasts animate in with `animate-overlay-in`, `animate-pop-in` and
`animate-toast-in`, defined in the `@theme` block of `index.css`. Components apply them with the
`motion-safe:` variant, so nothing moves when the user prefers reduced motion. Closing is instant.
Only the empty scrim fades; content moves without fading, because axe checks contrast at whatever
opacity it finds.
